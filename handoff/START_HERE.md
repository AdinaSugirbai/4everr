# Дайын кодты төрт адам өз commit-імен қалай салады

Бұл архивтер жаңа тапсырмалар ғана емес: дайын сайттың бастапқы коды төрт бөлікке бөлінген. Төртеуі бірге соңғы Career Studio UI нұсқасын құрайды.

**Бұрын бір commit-пен салынған `feature/career-studio-ui` тармағын `dev`-ке қоспаңыз.** Ол тек толық нұсқаның анықтамалық көшірмесі болып қалады. Төрт бөлік қазіргі `dev` негізіне есептелген (база: `27d0bfa893cb82f2ef76efc4e47b6903e5f3d090`). Егер толық тармақты біріктіріп қойған болсаңыз, оны жойып/reset етпей, алдымен жағдайды тексеру қажет.

## Ең қарапайым жұмыс реті

1. Бірінші адам ZIP-ін ашады. VS Code-та репозиторийді ашады, `dev`-тен өзінің feature тармағын жасайды.
2. Өз ZIP-індегі `files` папкасының **ішін** репозиторий түбіріне көшіреді. GitHub-та бөлек `files` папкасы пайда болмауы керек.
3. Өзгерістерін тексереді; Source Control-да тек өз файлдарын stage етіп, өз аккаунтымен commit/push жасайды. Тармақ атауы мен командалар әр архивтегі `READ_ME_FIRST.md` ішінде берілген.
4. GitHub-та `dev`-ке PR ашады. Бір командалас қарап, merge жасайды.
5. Екінші адам жаңартылған `dev`-ті pull жасап алады да, екінші ZIP-пен дәл осыны қайталайды. Одан кейін үшінші, соңында төртінші.

Нәтижесінде төрт адамның өз commit-тері және төрт бөлек PR болады. Әрқайсысы толық ZIP-ті қайта жүктемейді. Файлдар қабаттаспайды.

Әр ZIP ішіндегі `FILES.txt` нақты файл тізімін береді. `READ_ME_FIRST.md` пен `FILES.txt` — сыртқы нұсқаулықтар, оларды репозиторийге көшіру қажет емес.

## Commit авторлығы

Әр адам өз GitHub аккаунтын қолданады және GitHub-та расталған өз email-імен commit жасайды. Қажет болса, GitHub Settings → Emails бетіндегі өзінің `noreply` email-ін пайдалануға болады. Басқа адамның атын немесе email-ін қоймаңыз.

GitHub Commits/PR тізімінде үлес бірден көрінеді. Профильдегі contribution графигі default тармаққа біріктіру мен GitHub ережелеріне байланысты бөлек есептеледі.

## Маңызды

Бұл — UI кезеңі: деректер браузерде сақталады, серверлік аккаунттар мен нақты жариялау әлі қосылмаған. Барлық экрандар төртінші бөлік біріктірілгеннен кейін қолжетімді болады. Бұл жинақтарды дайындау кезінде GitHub-та қосымша commit немесе merge жасалған жоқ.
